- [x] 在运行系统确认 `mmcblk1` 为 MMC/eMMC `S40004`。

- [ ] 经明确风险评估后选择恢复演练方式；**不在 D01 贸然刷机**。

## C. 问题与风险

- `/dev/mmcblk1boot0`、`mmcblk1boot1` 是 eMMC 硬件分区，不能和普通 p1/p2/p3 混同。
- 不知道镜像精确对应关系时，**禁止**执行 `dd of=/dev/mmcblk1`、`mmc write`、`mmc erase`、`saveenv`、覆盖 Kernel / DTB / U-Boot 等操作。
- 串口不等于文件传输通道；可使用已验证的 ADB、网络或者厂商工具进行后续文件传输。
- 启动日志中发现 `findtee`、文件系统识别提示及关机 WARNING，应保留问题记录，而不是尝试盲目修复。

## D. D01 退出条件

1. 能明确标出**板子型号 + 软件版本 + 现存镜像来源**。
2. 能解释 U-Boot → Kernel/DTB → `/dev/mmcblk1p2` → Buildroot 的真实启动路径。
3. 已保存完整上电启动日志及原厂恢复所需资料的校验信息。
4. 已确定一个可信的恢复入口，恢复步骤来源于原厂材料并经过非破坏性核对。
5. 本阶段 Git 记录可追溯；未将未经验证的恢复任务标为完成。
