# G2-R3：系统健康检查主机阶段记录

状态：**PARTIAL / BLOCKED**。G1、G2 的板端验收仍为 BLOCKED。
本记录对应本地 `8bd2a845` 之后的独立主机工作；未推送，未连接或操作开发板。

## 1. 已冻结的健康策略

用户确认 GPIO、AP3216C（I²C）、本地网络和 Gateway 都是必需检查项。独立 DATA 尚未建立且跨槽数据策略未经验证，因此 DATA 为 **UNKNOWN**，此时不放行系统确认。不能用某一槽内的 `/opt/smartgateway` 目录存在代替共享数据和回滚兼容性验证。

- 必需项：系统/试启动身份、Supervisor 进程管理、Gateway 本地业务、GPIO、AP3216C、局域网络和 DATA/未完成事务。
- 状态：HEALTHY、DEGRADED、UNHEALTHY、UNKNOWN。必需项任一非 HEALTHY，不满足本地健康条件。外部服务不可达或未知可记为 DEGRADED，不能单独当成本地系统损坏。
- 只有必需项持续健康且达到配置的稳定窗口，才可能进入最终授权检查；观测超时、超过最大间隔、健康中断、身份/时间回退会清除或使证据无效。
- 实际确认仍需可信事务 ID、同一 boot_id/槽位/重试次数、受信数据来源、互斥和最终写入前复核。本次没有实现或开放生产确认。

## 2. 本次实现

### 2.1 只读诊断程序

`bsp/apps/boot_ab/sgw_system_health --once` 是**主机开发用只读诊断入口**，不是已部署的常驻服务，也不提供确认命令：

- 使用固定的实际 `/proc` 路径和当前 root 设备身份检查；不接受命令行健康结果或测试路径。
- 在具备条件时只读检查 U-Boot 环境和 trial 状态；实际启动事务唯一标识还未接入，所以即便观察到 trial，整体系统健康仍为 UNKNOWN。
- 使用 Supervisor 的原有 `STATUS` IPC 协议，不重写 Supervisor。新增探针检查 Unix socket 对端凭据、文件和路径所有权/写权限、Supervisor 可执行文件身份、Gateway 子进程关系与 PID/starttime 以及 Gateway 可执行文件身份。不能证明归属时返回未知；领养而非子进程的情况暂时拒绝。
- 即使上述进程检查成功，也只证明管理状态，不能证明 Gateway 的业务处理、设备或网络健康。
- Gateway 业务、GPIO、AP3216C、本地网络和 DATA 的生产探针尚未接入，全部报告 UNKNOWN；外部健康也尚未采集。程序始终返回 `confirmation=DISABLED` 和非成功退出码。
- 固定路径（包括 `/usr/sbin/fw_printenv`）及目标系统的权限/工具路径尚未板端验证；缺失或不满足时只能得到 UNKNOWN。现有环境读取子进程没有整体超时保护；诊断程序不应作为生产常驻服务部署，须先完成有界读取与异常清理。

不会调用 `fw_setenv`、写启动状态、启动/停止 Gateway 或操作 Watchdog。尚未注册到 init，不提供自动部署。

### 2.2 健康评估模型

`system_health.c` 是独立的**纯计算模型**：七项本地检查分别参与聚合，外部故障只形成 DEGRADED；跟踪单调时间、采样间隔、稳定窗口和超时，绑定 boot_id、候选槽、bootcount 及 64 位十六进制事务标识。非法状态、时间倒退或身份变化使跟踪器失效。

模型不读取真实设备、不验证传入样本真实性，也**没有连接到生产确认**。测试可注入模拟身份和检查结果，因此模型中的“稳定健康”不是可用于升级确认的凭据。当前启动环境没有已经核实并绑定包摘要的 transaction ID；需要先由受信更新流程提供并持久化它，才能实现真正的事务身份绑定。

### 2.3 启动环境输入收紧

`fw_env_backend_load` 不再以 C 侧默认值补齐缺失的关键状态：七个核心 A/B 变量必须存在且不能重复；数值和槽位/状态格式非法时拒绝；输出可能被截断或内容不一致时拒绝。已有的 CRC 警告拒绝逻辑保留。文件镜像测试只验证工具行为，不证明 eMMC 掉电原子性。

## 3. 主机验证与解释

在由 `8bd2a845` 导出的干净虚拟机测试副本中执行：

| 项目 | 结果 |
|---|---|
| A/B 状态机、环境后端及根身份 | 状态机 100/0、环境后端 31/0；根身份拒绝测试通过 |
| 健康模型 | 195 项断言、0 失败；含每个必需项的 UNKNOWN/DEGRADED/UNHEALTHY、稳定窗口、时间与身份变化、远端降级和纯内存确认模型 |
| G1/G2/G2-R3 Python | 25 项通过；含双份环境损坏、真实本地 Unix socket 与子进程模拟、错误 UID/可执行文件、过期 PID、超时、不安全目录及确认禁用 |
| Supervisor 干净测试 | IPC 58/58、Supervisor 35/35 |
| 用户态交叉编译 | `sgw_bootctl`、`sgw_watchdog_guard` 和诊断程序均为 ELF32 ARM，最高 GLIBC_2.28；目标 RootFS 兼容性未验证 |

Unix socket 测试使用临时目录、Python 模拟服务和 sleep 子进程，验证身份检查算法，不代表真实 Supervisor/Gateway 板端集成通过。模型中的正向确认只调用内存状态机，并不调用生产 `fw_setenv`；生产 `sgw_bootctl confirm` 和 Watchdog 确认仍由原来的失败关闭保护阻止。原始主机日志保存在本次工作区，不纳入仓库。
