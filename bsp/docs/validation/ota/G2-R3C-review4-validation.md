- **G2-R3C：BLOCKED；生产确认默认拒绝。** 现有 Gateway 本地标记覆盖队列、消费线程及部分编解码，不能证明业务入口到远端应用的完整处理，也不能证明远端应用处理成功。即便调用者具有 root 身份，生产 `r3c_coordinator_confirm` 仍拒绝，且在任何事务或环境写入之前返回。历史 `HOST-ACCEPTED` 描述仅为当时的历史结论，不代表当前安全放行。

## 修复与限制

1. **清单中的 libc 符号链接。** 仅为 `/lib/libc.so.6` 接受同目录的 `libc-<版本>.so` 单层链接，对其实际文件进行摘要核验；绝对路径、向上跳转、链式链接以及不支持的链接形式拒绝。镜像与运行态分别核验。其他链接布局，包括 `/lib` 本身为符号链接，仍可能被拒绝，属于待扩展的兼容性边界。
2. **块设备拓扑。** 核验 sysfs 中目标、受保护槽与挂载设备的拓扑；关系目录缺失、不可读、有 holder 或 slave 等未知/堆叠关系时拒绝。此策略对无关的映射盘也可能拒绝，优先保持安全。当前挂载信息只覆盖当前挂载命名空间，尚不能证明其他命名空间没有挂载；不得据此放行真实写槽。
3. **验签与解析时限。** 先验证签名及有界清单、再检查镜像摘要，最后才调用 debugfs；每个 debugfs 子进程限时 10 秒，整份清单核验限时 60 秒，超时或异常拒绝。此时限可能使较慢设备上的合法镜像被拒绝；处理器进程本身不是沙箱，恶意解析器风险及不可中断内核 I/O 的处置仍需专项验证。
4. **断网诊断。** Gateway 上游断开且已有业务消息等待时，可从真实队列消费受控本地标记；保留待发送业务消息，不将标记发送到上游。恢复连接后，隔离测试验证原消息仍能送达。该诊断仅表明局部处理链可响应，不证明远端业务健康，也不解除生产确认禁令。
5. **目标 RootFS 依赖。** 原 G3 基线未启用 debugfs。G3 的标准构建脚本现显式启用 `BR2_PACKAGE_E2FSPROGS_DEBUGFS=y`，离线镜像测试要求存在 `/usr/sbin/debugfs` 或 `/sbin/debugfs`。直接绕过该脚本构建的镜像仍须自行纳入依赖；是否适合目标设备及其攻击面需要板端与安全评审。构建测试不等于实板升级验收。
